> **评估对象**：`MisterBooo/llm-interview-questions`（main @ `320048c`，CC BY-SA 4.0）
> **评估日期**：2026-10-25 · **评估方式**：AI 协作会话（与 dongf9527）

## 一、项目全景

### 1.1 基本盘

作者吴师兄是 `LeetCodeAnimation`（76.7k stars）的作者，在算法教学内容的体系化上有长期积累。该仓库定位为**中文 LLM 面试题库**，收录 100 道题目、100 张 SVG 图解，覆盖 14 个模块。与常见面经仓库不同，它的每道题在 GitHub 端只保留约 50 字的「30 秒回答」摘要（实测平均 52 字），完整答案引导至官网——这是一个明确的知识付费引流设计，也是利用该仓库时必须正视的前提。许可证为 CC BY-SA 4.0，允许署名再分发与二次开发，衍生内容需以相同许可证共享。

### 1.2 内容结构

14 个模块的题量分布并不均衡，重原理轻工程的取向明显：

| 模块 | 题量 | 模块 | 题量 |
|------|---:|------|---:|
| 模型架构 | 20 | Prompt 工程 | 3 |
| 模型训练 | 11 | 微调 | 4 |
| RLHF 与对齐 | 8 | 文档处理 | 1 |
| Agent | 8 | 知识图谱 | 2 |
| 多模态 | 8 | RAG 基础 | 6 |
| 评估监控 | 8 | 向量检索 | 9 |
| 推理优化 | 7 | 重排 | 5 |

![模块题量分布](../assets/chart_modules.png)

图解（SVG）的前缀分布同样集中在 RAG（38 张）、架构（24）、训练（16），与题量分布基本对应，即**几乎每题一图**的图解密度在同类仓库中较为罕见。

### 1.3 质量控制机制

仓库最有价值的机制设计有两处。其一是 **B/C 来源分级**：B 级 74 题附有可回查的参考资料（共 154 个去重链接，其中 115 个指向 arXiv 论文），C 级 26 题则不附来源。这意味着近四分之三的题目观点可以被追溯到一手文献，学习者可以自行验证答案的可靠性，而不必全盘信任作者。其二是 `review-manifest.json` 的**哈希闸门复核**：每题内容哈希被锁定在清单中，任何静默修改都会导致复核失败，这对防止题解被无审校地篡改提供了工程化保障。

## 二、优势与局限

### 2.1 优势

一是**可回查性**。B 级题目平均每题挂 1–2 条 arXiv 引用，把「背面经」升级为「顺藤摸瓜读论文」，这对求职者构建经得起追问的知识体系至关重要。二是**图解密度**。100 张 SVG 与题目一一对应，将 KV Cache、RoPE、DPO 等抽象机制可视化，天然适合二次加工为讲义。三是**闸门机制可复用**。review-manifest 的哈希锁定思路可以迁移到任何内容型仓库的质控流程。四是**模块覆盖全栈**，从架构、训练到 RAG、Agent、评估监控，一库即可俯瞰 LLM 工程版图。

### 2.2 局限

一是**GitHub 端只有摘要**：52 字的「30 秒回答」无法支撑深度学习，完整答案需要到官网获取，仓库本身更接近「知识地图」而非「教材」。二是**模块题量失衡**：文档处理仅 1 题、知识图谱 2 题、Prompt 工程 3 题、微调仅 4 题，而微调恰恰是求职作品集的高频刚需。三是**无可运行代码**：纯文档仓库，所有实验需自行搭建。四是部分前沿主题覆盖较薄（如 MLA、推理期 scaling 仅零星涉及）。

## 三、利用策略与二次开发方向

基于上述评估，该仓库的正确定位是**知识地图 + 评测素材 + 教学素材**，而不是教程。由此延伸出三条利用线：其一，**系统学习**采用三层阅读法——先读 GitHub 端摘要建立索引，再读官网全文理解论证，最后对 B 级题回查 arXiv 一手资料；其二，**二次开发**将 100 题转化为 JSONL 格式的中文 LLM 评测集（本计划旗舰项目），顺带复用其哈希闸门机制管理评测集版本；其三，**教学分享**将 SVG 图解按模块重组为讲义。所有衍生分发需遵守 CC BY-SA 4.0：保留原作者署名，衍生内容同许可证共享。

## 五、风险与裁剪优先级

六个高频坑及规避手段：

| 坑 | 典型症状 | 规避方法 |
|----|---------|---------|
| Colab 会话回收 | 长训练被中断，权重丢失 | checkpoint 每 epoch 存 Drive，产物即存即同步 |
| 显存 OOM | 微调时 CUDA out of memory | 按 batch → rank → 序列长度顺序降；4bit 优先；开 gradient_checkpointing |
| 中文字体缺失 | 图表中文变方块 | matplotlib 先 addfont 再设 rcParams |
| 依赖版本冲突 | peft 与 transformers 不兼容 | 每实验独立笔记本，装后重启运行时，固定版本号 |
| 评测不可复现 | 两次跑分差异大 | temperature=0 + 固定随机种子，报告注明版本时间 |
| 仓库内容过期 | 上游更新后图解变化 | 本地克隆锁定 commit，引用注明复核日期 |

**时间不足时的裁剪顺序**：若每周可用时间不足 7 小时，先砍实验 7（GraphRAG，改读 LightRAG 文档替代）；再砍实验 9（DPO，改为精读图解与论文）；再把实验 6 并入实验 5（只跑一次重排对比）。**底线三实验：实验 1（手写注意力，原理基石）、实验 4（RAG 链路，应用岗高频）、实验 8（QLoRA 微调，差异化证据）**——若只剩一周，就只做这三个实验加全量题目的三层阅读。
